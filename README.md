# Intus

Live at https://intus.fit. A personal health tracker: daily log, progress charts, history and bloodwork, on a Supabase database that only answers to the owner's login. React, TypeScript, Vite and Tailwind, deployed on Vercel.

## Run it

```
npm install
npm run dev        # local dev server
npm test           # unit tests (Node's built-in runner, TypeScript run directly)
npm run typecheck
npm run build      # typecheck, then production build into dist/
```

Node 22.18 or newer is needed, because the tests run TypeScript through Node's built-in type stripping.

The app talks to the production Supabase project by default. `.env.example` lists the two variables that point it elsewhere. The publishable key is public by design, and row-level security is what protects the data (see `supabase/README.md`).

## Layout

| Path | What lives there |
| --- | --- |
| `src/lib/` | Plain logic with no UI or network: trend detection, critical-value checks, reference ranges, `nutrition.ts` (BMR by three formulas, maintenance calories, the calorie change for losing or gaining, a protein starting point; the formulas are the ones on calculator.net's calorie calculator) and `age.ts` (age from an exact date of birth, so it goes up on the birthday) |
| `src/features/bloodwork/` | The Bloodwork screen. `model.ts` turns table rows into what is shown, and the components only draw it |
| `src/features/dashboard/` | The signed-in app as separate pages: `pages.ts` lists them (Dashboard, Today, Goals and habits, Bloodwork, Supplements, Progress, with Account at the right of the bar) and `usePage.ts` keeps the page in the `#hash`, so the back button and links work (old `#sleep`, `#history` and `#screening` links land on the page that holds them). `TopNav.tsx` is the bar across the top, behind frosted glass. `PageHeader.tsx` gives every page its title and its own ASCII artwork; the ribs down the left side belong to the dashboard only |
| `src/features/home/` | The public homepage (About, Why this, Pricing, Knowledge base) and the small router: `/` is the homepage for signed-out visitors and the app for signed-in ones, `/signin` is sign-in (`/signin?mode=signup` opens Create account). `knowledge.ts` holds the supplement entries, `route.ts` the address rules, `pricing.ts` every word the site says about price (the homepage card and the `/pricing` page, `Pricing.tsx`; `test/pricing.test.ts` fails if it names an amount, a plan or a subscription before the pricing decision is made). `vercel.json` rewrites every path to `index.html` so `/signin` works on a reload |
| `src/features/mobile/` | On a phone browser the homepage is the whole site, and any other address shows a "Coming soon to iOS and Android" screen instead of the app. `device.ts` decides; tablets and desktops pass |
| `src/features/strength/` | The Strength card under Today: start a workout, add sets (exercise, kg, reps, optional RPE in half steps and a note), finish. Every change goes into an outbox in local storage first (`queue.ts`), then is sent; each send is an upsert or delete by an id made on the device, so resending is harmless and a closed tab or lost connection never loses a set. Unsent sets are marked "not sent yet". Rules in `model.ts` |
| `src/features/today`, `progress` | The daily log and the Nutrition targets card on Today; on Progress, the charts of the latest 30 entries, each with a Dive deeper that opens that chart's whole history, and habit streaks (`habits/streaks.ts`: calendar days, by each habit's own goal and direction, so a smoking habit reads "No Cigarettes") |
| `src/features/profile/` | The profile shared by every screen. The age is worked out from the date of birth each time it is read. `DetailsCard.tsx` (on Goals and habits) edits sex, date of birth, height and activity, which the age, the lab ranges and the calorie suggestion come from |
| `src/features/photos/` | Photo check-ins, a card under Goals and habits. `model.ts` holds the rules (angles, limits, compare first and latest), `image.ts` resizes in the browser and re-encodes so location and camera tags never leave the device, `removeAll.ts` empties a folder and proves it. The pictures live in a private Storage bucket; see `supabase/README.md` |
| `src/features/sleep/` | The Sleep module on the Today page, with a small snapshot of it on the dashboard. Nothing derived is stored: `model.ts` checks an entry, `nights.ts` builds nights from what each source said (one source per night, never blended), `metrics.ts` works out time asleep and stages, `summary.ts` the averages (none under 5 nights), `ageBand.ts` the recommended range by age, `time.ts` circular clock statistics. The rules and the research behind them are in `docs/product/sleep-tracker.md` |
| `src/features/markers/` | The three kinds of marker, told apart by how a value arrives: **active** (pulled from a wearable or Apple Health and Health Connect), **daily** (typed in by the person towards the end of the day: habits, calories, weight) and **periodic** (blood results every 2 to 3 months, screenings, photo check-ins). `kinds.ts` places every personal table in one of them, and a test fails if a new table is not placed |
| `src/features/reports/` | Upload a lab report PDF on the Bloodwork screen. `extract.ts` reads it on the device (pdf.js, and Tesseract OCR for scanned pages, served from `public/ocr/`, which `scripts/copy-ocr.mjs` fills at build time), `parse.ts` finds each marker (names labs use are in `aliases.ts`), its value, unit, printed range and the sample date, and `review.ts` decides which rows start ticked. Nothing is saved until the person checks the table; units are never converted, and a unit that differs from the stored one leaves the row out until the person deals with it. A private copy of the PDF can be kept in the `lab-reports` bucket |
| `src/features/cycle/` | For women (by the sex in their profile), two cards under Goals and habits: Your cycle (log bleeding days with flow and optional symptoms; shows cycle day, usual cycle and period length once three cycles are logged; never predicts periods, ovulation or fertile days) and Conditions and life stages (PCOS with the person's own label, pregnancy, menopause and others). Pregnancy makes Intus use only printed ranges. Blood results show the cycle day they were taken on. Rules in `model.ts`; plan in `docs/product/womens-health.md` |
| `src/features/import/` | Import from Apple Health, in the Sleep section: the zip from the Health app's Export All Health Data (or export.xml), streamed through the browser with fflate and scanned line by line, so a large export is never held in memory. Keeps sleep, HRV and resting heart rate from the last year and turns them into rows with the iPhone app's mapping (`mobile/src/sync/mapping.ts`). Nothing but those rows leaves the device; importing again adds nothing twice |
| `src/features/supplements/` | The supplements you take (a multivitamin, creatine) with start and end dates, and a before/after comparison against what you log. No dose checks or warnings |
| `src/features/account/` | The Account page (at the right of the top bar): who is signed in, Sign out, and Delete account, which asks for the email to be typed back, calls `delete_my_account()` in the database (see `supabase/README.md`), clears what the app keeps on the device and signs out |

## Design

Separate pages under a frosted-glass top bar, inspired by Apple's large titles and grouped cards, in a Swiss red and paper palette with an ASCII streak. The tokens live in `src/styles/index.css`.

- Colours: red `#A31621` for actions and the current section, paper `#E5ECE9`, green `#12695F` for on track, ink `#1F1300` for text, and `#A3988F` for the background dots. An ochre (`#8A5A14`) marks "close" and "check this".
- Type: Inter for titles and text, JetBrains Mono for numbers, labels and the ASCII art, both set heavier than their defaults (body 500, medium 600, semibold 700). Both fonts are bundled, so no font request leaves the browser.
- Layout: on desktop the section index is pinned to the left edge and the content fills the rest of the width, up to 1,640 px.
- Background: a grid of small dots (3 px on a 22 px pitch, set in `src/components/dot-ground.tsx`). On a desktop pointer the dots under the cursor light red and fade.
- Motion: sections fade up once, section titles light red as they climb the upper part of the window (a gradient pinned to the viewport and clipped to the letters, with no script; mouse and trackpad only, plain ink on touch screens, in print and in forced colours), numbers settle into place, bars fill, the ASCII shapes turn slowly and pause off screen. On the statue bust a band of lighter red crosses the stone every eight seconds and the chest rises and falls a little, also paused off screen. On Today to Progress the engraved pictures move slowly: sand runs through the hourglass, the archer's bow gives and springs back, bubbles rise in the test tubes, pills rattle, and the boulder creeps up the slope and rolls back down. They draw at 15 frames a second, pause off screen and in a hidden tab, and show one still frame, exactly the generated art, under reduced motion. Everything stops under reduced motion. No confetti, particles, sounds or emojis.
- The UX journey, onboarding questions, page map and visual language are on the Miro board "Health OS: UI/UX revamp" (the board still carries the old name).
- Artwork: the ribs in the desktop section index are real characters plus a traced solid layer, drawn as SVG by `src/components/ui/ascii-picture.tsx` from `src/components/art/ribs.ts`. That file is generated by `scripts/ascii_art.py` from `docs/art/ribs-source.webp`, and the same script can turn any one-colour artwork into ASCII. `src/assets/art/statue-bust.webp` is the statue bust, red on transparent, shown on the homepage and on the sign-in screen through `src/components/statue-bust.tsx`, which adds the light and the breathing (the picture's own shape masks the light, so it falls only on the statue). The five pictures on Today to Progress (hourglass, archer, test tubes, pill bottles, Sisyphus) are tone grids of about 150 to 200 columns instead of traced shapes: `scripts/ascii_scene.py` (`python3 scripts/ascii_scene.py docs/art/scenes-source.webp src/components/art`) turns `docs/art/scenes-source.webp` into `src/components/art/scene-*.ts`. It blurs the engraving's halftone dots away first, which is what keeps the shading smooth, and picks symbols from a ramp measured in JetBrains Mono Bold, so the steps are even. `src/components/ui/ascii-scene.tsx` reads the tones back and `scene-engine.ts` makes each frame: soft handles slide or turn a region by a few cells, a scene can paint on top (the sand, the bubbles), a band of light crosses now and then, and every cell picks its character again. No frames are stored, the same time always gives the same frame, and each picture is its own chunk, fetched when its page opens. A soft red layer under the characters (one pixel per character) stops the dark parts reading pink at small sizes.
- Logo: option B, the section cut (chosen 11 Oct 2026), a slash that is solid at its head and dissolves into halftone dots. The three options and the files are in `docs/brand/logos/`.

## Bloodwork and safety

- A reading counts as critical when it reaches a stored critical limit (inclusive). A marker with no limit can never be flagged as critical.
- Each result is flagged against the range printed on its own report when it has one (stored with the result; the lab chose it for the person's sex and age). Without one, the marker's usual range is used only when it applies to the person: usual ranges that are men's ranges (`biomarkers.ref_sex`) are never used for a woman, or for someone whose sex is not recorded, and the result shows no range instead. The rule is `src/lib/ranges.ts`; the screen says which range each result was read against.
- The only disclaimer in the app is the one line in the footer. No screen carries its own warning or caveat.
- Results can be typed in on the Bloodwork screen. They are stored with the source `manual`, shown as "entered by you", and can be deleted from the screen. Only plain decimals are accepted, a second result for the same marker on the same day is refused, and a number ten times outside the usual range asks for confirmation in case it was typed in the wrong unit.
- Arrows compare the latest result with the one before. A statistical trend (Mann-Kendall) needs five results, so most markers will not show one yet.
- The app does not assess medicines or doses. Supplements are recorded with their dates and schedule, and nothing more.
- "What changed since you started" (Supplements tab) sets the 28 days before a supplement's start date against days 8 to 63 after it, using only days you logged. It says nothing until each period has 10 logged days, calls a change only when it is both a medium-sized shift and clearly larger than ordinary day-to-day variation, never colours a change good or bad, and flags other supplements started or stopped close to the same time. Habits are compared too (a yes or no habit as the share of logged days it was a yes, a count or amount as its number; a day with no entry is not a no), and so are heart rate variability and resting heart rate from `cardio_metrics`, averaged per day, once a phone sync fills that table. Bloodwork is shown as one result before and one after, never as a trend. It is an observation of two periods and cannot show that a supplement works. The rules and their numbers live in `src/features/supplements/effect.ts` and are pinned by `test/supplements.effect.test.ts`.
- Each marker on the Bloodwork screen has an "i" that opens a short note on hover, tap or keyboard: what the marker is, common reasons it runs high or low, and general habits that affect it, with the range the person's result was read against and a link to MedlinePlus (by LOINC code, through MedlinePlus Connect). No medicines, no doses, no diagnosis, and no extra disclaimer, following the one-footer rule. The text is `src/features/bloodwork/markerInfo.ts`; `test/markerInfo.test.ts` fails if a live marker has no entry, if an entry names a dose or a common medicine, or if a LOINC check digit is wrong.
- The homepage knowledge base is about supplements only: which blood results a supplement can move, in which direction and why. It never scores or judges. The entries are plain data in `src/features/home/knowledge.ts` and should be reviewed against sources before launch (the biotin entry follows the FDA's safety communication).
- Data the checks cannot trust (a reading with no biomarker, a threshold that is not a number) stops the screen with an error instead of being skipped.
